Short definitions used across industry and enterprise engineering conversations. Expand over time.

| Term | Meaning |
|------|---------|
| **ADR** | Architecture Decision Record — a short document capturing a significant technical decision and its context. |
| **Baseline** | A minimum agreed set of practices or controls that all teams follow. |
| **CI/CD** | Continuous Integration / Continuous Delivery (or Deployment) — automated build, test, and release pipelines. |
| **Enterprise standard** | Practices suited to multi-team, regulated, or long-lived systems: governance, supportability, auditability, and risk management. |
| **Industry standard** | Widely accepted practices across organizations (often vendor-neutral or backed by recognized bodies). |
| **Observability** | Ability to understand system state from logs, metrics, and traces (and related signals). |
| **Runbook** | Operational instructions for diagnosing and resolving known situations. |
| **SLA / SLO / SLI** | Service Level Agreement / Objective / Indicator — contractual or internal reliability targets and measurements. |
| **SSO / RBAC** | Single Sign-On / Role-Based Access Control — identity and authorization patterns common in enterprise tools. |
| **Technical debt** | Deferred work that increases future cost or risk if left unmanaged. |
